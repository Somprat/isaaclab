## Working conventions

- Keep explanations precise and direct. When making changes, focus on why they were needed, which files changed, and what changed in each file. Distinguish completed work from proposed work.
- Keep code simple and readable. Choose the smallest clear implementation that meets the requirement; avoid unnecessary abstractions and overengineering.
- Preserve unrelated changes. Do not start training unless requested.
- Run workspace Python tools with `uv run --project IsaacLab --no-sync python`.
- Keep diagnostic replays separate from production controllers and checkpoints. State whether a replay uses physics, policy inference, prescribed body motion, or exact joint placement. Kinematic success does not establish balance or actuator tracking.
- Build/run `wb_humanoid_mpc` inside `wb-mpc-dev`: the host project is mounted at `/wb_humanoid_mpc_ws/src/wb_humanoid_mpc`, with `.docker_ws` at `/wb_humanoid_mpc_ws`. `LIP/` is not mounted. Source ROS Humble and the workspace install setup before `ros2 run`. Container-created files may be root-owned on the host.

## Torso-height to LIP, MPC, and PPO pipeline (2026-11-22)

- Intended flow: choose a `torso_link` frame-origin height; find a double-support G1 posture at that height; measure its whole-robot CoM height; generate LIP CoM/foot trajectories from that height and gait parameters; obtain compatible MPC pelvis and non-arm joint trajectories; train PPO for legs and waist while online differential IK owns the arms. The origin-height target replaces the earlier torso-inertial-CoM target because Isaac's merged torso and the URDF torso have different inertial CoMs.
- Local calibration executable `humanoid_centroidal_mpc_height_calibration` is in `wb_humanoid_mpc/humanoid_nmpc/humanoid_centroidal_mpc_ros2/src/CentroidalMpcHeightCalibration.cpp`, registered in that package's `CMakeLists.txt`. It iterates a pelvis-height command under standing, zero-velocity MPC until the torso origin is within 1 mm after settling, then records the posture, torso CoM, whole-body CoM, and contact frames in schema-2 `g1_torso_origin_height_calibration` JSON. Use `--torso-origin-height`; failures include unreachable pelvis bounds, lost double support, and iteration exhaustion. Build target `humanoid_centroidal_mpc_height_calibration` in the container's package build directory. This is a centroidal model rollout, not a physics validation.
- `wb_humanoid_mpc/generated_motions/g1_height_calibration_torso_origin0810.json` converged in five iterations for requested torso origin 0.81 m: achieved 0.810539 m, pelvis 0.756556 m, whole-body CoM 0.693038 m above near-zero contact frames. The older 0.98 m torso-CoM JSON was removed. These calibration files were uncommitted local changes at this handoff.
- `LIP/LIPM/demo_LIPM_3D_vt.py --height-calibration <json>` accepts successful schema-2 calibration and uses `whole_body_com_height - mean_contact_frame_height` for LIP. It overrides `--com-height` and initial-state CoM Z; the initial-state file still supplies CoM XY/velocity and feet. A verified 0.81 m calibration run generated constant LIP CoM height 0.693040 m. The older `--torso-com-height` option uses an approximate fixed offset and cannot be combined with calibration. `LIP/LIPM/capture_g1_initial_state.py` and `LIP/initial_states/g1_reset.json` now include torso origin and CoM positions. These files were locally modified at this handoff.
- Calibrated initial state (2026-11-23): `capture_g1_initial_state.py --height-calibration <json> --output <json>` places the Isaac robot at the calibration's root pose (ZYX Euler to quaternion; root z lifted by the 2 um mean contact-frame offset so MPC contact frames sit at z=0) and 29 joints. The same posture is used as the nominal-PD default for the contact check. `LIP/initial_states/g1_torso_origin0810.json` has zero placement error, torso origin 0.810541 m, CoM (0.036447, 0, 0.693040) m, Isaac soles at x 0.001518 m, both feet loaded. MPC contact frames are the same points +3.5 cm in X. `LIP/generated_trajectories/steps_010_020_030_first050_g1_torso_origin0810.npz` uses this state, the 0.81 calibration, and `LIP/gait_schedules/steps_010_020_030.json`. Its t=0 CoM matches the JSON to 4e-8 m, and its feet XY match exactly. It supersedes `steps_010_020_030_torso_origin0810.npz`, which used reset-pose XY: CoM 12.7 mm and feet 27.5 mm further back.
- LIP to MPC export: `LIP/scripts/export_lip_to_mpc.py <npz> [--dt k*0.005]` checks schema 3, world_z_up, left/right order, uniform time from 0, support mask (no flight, stance feet at z=0, starts in double support), and constant CoM equal to a successful schema-2 calibration inside wb_humanoid_mpc/. It writes `wb_humanoid_mpc/lip_references/<stem>.csv` ('#' metadata, then CSV: time, contact flags, CoM pos/vel, foot pos/vel). Feet are exported at MPC contact frames (sole +0.035 m along heading). `generated_motions/` is root-owned, so the host cannot write there. `humanoid_centroidal_mpc_random_reference_generator --lip-reference <container csv>` loads and validates it, then exits 0. Checks: format, frame, exact header, 21 finite fields per row, 0/1 contacts, uniform dt, no flight, stance z=0, CoM z = lip_com_height, calibration file visible. It rejects step, velocity-condition, and random-command options, and also `--num-motions` != 1 or a `--duration` longer than the file. Tracking (2026-11-23): `FootReferencePlan` (`humanoid_common_mpc/.../swing_foot_planner/FootReferencePlan.h`) is now the interface behind `setStepReferencePlan`. `StepReferencePlan` implements it, and so does the new sample-backed `LipReferencePlan.h`. The LIP plan sets the contact mode schedule from the support mask, with each change taking effect at the first sample that shows it; LIP has no double support after the 0.8 s startup, so it switches LF and RF directly. Feet xy/z are Hermite-interpolated from sample positions and velocities (velocities linear), so any time in the horizon is queried. `SwingTrajectoryPlanner::setVerticalReference` replaces spline foot heights. CoM targets use knots at each LIP sample in the horizon. Momentum head = LIP CoM velocity, and base target = LIP CoM + current base-minus-CoM offset. Joint targets remain nominal. Default `--duration` = reference length − 1.2 s horizon. The NPZ adds `lip_com_pos_w`, `lip_com_vel_w`, `lip_foot_pos_w`, `lip_foot_vel_w`, `lip_contact`, and `com_pos_w`. Rebuilt via colcon: humanoid_common_mpc, humanoid_centroidal_mpc, humanoid_common_mpc_ros2, humanoid_centroidal_mpc_ros2, humanoid_centroidal_mpc_test, and g1_centroidal_mpc (Release, BUILD_TESTING=ON). `test_lip_reference_plan` and `test_step_reference_plan` pass. Export format is now `lip_reference_csv_v2`, which adds the calibrated base pose (root z − mean_contact_frame_height) and 29 joint positions. LIP mode starts MPC in that posture and uses its 12 leg joints as nominal targets. 1.5 s smoke runs: the initial CoM and contacts match LIP exactly, contacts match LIP, and swing contact z tracks LIP to about 0.3 mm. The robot still rises in the first 0.8 s: pelvis 0.7567 → 0.778 m, support knee 0.67 → 0.28 rad, and max CoM z error 2.1 cm (mean 1.4 cm, versus 2.2 cm when starting from the default posture). Disabling the leg torque costs changed that by only about 2 mm. The base z weight is 150, base x/y 0, and CoM-velocity x/y 500. The upward bias is undiagnosed, and it also explains why calibration needed a 0.657 m pelvis command to reach 0.7566 m. CoM y lags up to 2.6 cm. Torso height cost (2026-11-23): in LIP mode, the generator adds a `FrameHeightCost` state cost before `SqpMpc` copies the problem. It is 0.5·w·(torso_link origin z − target)² over every horizon, with an analytic Pinocchio Jacobian and Gauss-Newton Hessian. Target defaults to the CSV `requested_torso_origin_height` (0.81) and can be set with `--torso-origin-height`. `--torso-height-weight` defaults to 10000; 0 disables it. 5 s run: torso 0.8086–0.8144 m, CoM z error ≤ 4.4 mm, knees ≥ 0.51 rad, contacts match LIP. Remaining issue: CoM xy error grows by about 3 mm per step (2.6 → 3.8 cm by 5 s) because base x/y position weight is 0 and only CoM velocity is tracked. No full trajectory has been generated.
