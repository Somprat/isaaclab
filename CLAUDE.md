## Working conventions

- Keep explanations precise and direct. When making changes, focus on why they were needed, which files changed, and what changed in each file. Distinguish completed work from proposed work.
- Keep code simple and readable. Choose the smallest clear implementation that meets the requirement; avoid unnecessary abstractions and overengineering.
- Preserve unrelated changes. Do not start training unless requested.
- Run workspace Python tools with `uv run --project IsaacLab --no-sync python`.
- Keep diagnostic replays separate from production controllers and checkpoints. State whether a replay uses physics, policy inference, prescribed body motion, or exact joint placement. Kinematic success does not establish balance or actuator tracking.
- `wb_humanoid_mpc` builds and runs inside the `wb-mpc-dev` Docker container. Host `wb_humanoid_mpc/` is mounted at `/wb_humanoid_mpc_ws/src/wb_humanoid_mpc`, and `wb_humanoid_mpc/.docker_ws` at `/wb_humanoid_mpc_ws`. `LIP/` is not mounted. ## Torso-height to LIP, MPC, and PPO pipeline (2026-11-22)

- Intended flow: choose a torso_link origin height; find a double-support G1 posture at that height; measure its whole-robot CoM height; generate LIP CoM/foot trajectories from that height and gait parameters; obtain compatible MPC pelvis and non-arm joint trajectories; train PPO for legs and waist while online differential IK owns the arms.
- The calibration target is the `torso_link` frame-origin height, not the torso CoM. This replaced the earlier torso-CoM version. Torso-CoM definitions differ between models: see the Isaac/URDF comparison below.
- Calibration executable: `humanoid_centroidal_mpc_height_calibration`, from `wb_humanoid_mpc/humanoid_nmpc/humanoid_centroidal_mpc_ros2/src/CentroidalMpcHeightCalibration.cpp`, registered and installed in that package's `CMakeLists.txt`. It reuses the random reference generator's MPC setup, rollout, and full Pinocchio model. It runs stance gait with zero velocity and default arm/waist targets, with arm swing off.
  - Each iteration runs the MPC with a fixed pelvis-height command until settled: over 0.5 s, torso z span below 0.2 mm, CoM speed below 2 mm/s, and joint speed below 0.01 rad/s.
  - It then measures the torso origin. It corrects the pelvis command with a damped secant step: gain 0.8, cap 0.05 m per step, with the measured d(torso)/d(command) slope clamped to [0.02, 2]. The MPC follows only roughly 0.1–0.3 of each command change because its default-joint-posture cost resists.
  - Tolerance is 1 mm and the iteration limit is 25; command bounds are 0.30–0.85 m.
  - Failure statuses: `unreachable_pelvis_bound`, `max_iterations`, `lost_double_support` (exit code 2).
  - It writes schema-2 JSON (`g1_torso_origin_height_calibration`) on success and failure. Contents: posture, measured heights, torso CoM, whole-body CoM, contact-frame positions, and per-iteration history.
  - Contact frames are measured on the MPC model, because the full URDF model lacks them.
- Build only this target in the container: `cd /wb_humanoid_mpc_ws/build/humanoid_centroidal_mpc_ros2 && cmake --build . --target humanoid_centroidal_mpc_height_calibration`. The install symlink was added manually, so `ros2 run humanoid_centroidal_mpc_ros2 humanoid_centroidal_mpc_height_calibration --torso-origin-height 0.81 --output <json>` works. Other targets in that package were not rebuilt.
- Current calibration: `wb_humanoid_mpc/generated_motions/g1_height_calibration_torso_origin0810.json`, converged in 5 iterations.
  - Torso origin: 0.81 m requested, 0.810539 m achieved.
